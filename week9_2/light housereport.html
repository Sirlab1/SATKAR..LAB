What I found and what I fixed

The first Lighthouse run (Accessibility only) scored 85 out of 100. Each problem sits next to the fix I made for it.

Problem

Low color contrast

The light gray text, such as the task counts and section descriptions, was too faint against the white background.

→

Fix 1

Darker text color

Changed the gray to #4b5563, about 7.5:1 on white, which passes the WCAG AA minimum of 4.5:1.

Problem

Links without distinct names

Links like "Task 1" repeated in every week, so a screen reader user could not tell the weeks apart.

→

Fix 2

Descriptive link names

Added hidden text to each link, such as "Task 1 of Week 1", so every link has a unique accessible name.

Problem

No skip link or main landmark

Keyboard users had to tab through the header before reaching the content, and the page had no <main> region.

→

Fix 3

Skip link and main landmark

Added a "Skip to main content" link and wrapped the content in <main id="main-content">, meeting WCAG Level A 2.4.1.

Before and after screenshots

Both screenshots come from the Lighthouse tab in Chrome DevTools. Select an image to open it full size.

Conclusion

After fixing three accessibility problems, my Lighthouse accessibility score improved from 85 to 100. This activity showed me how color contrast, clear link names and keyboard navigation help people who use assistive technology.
